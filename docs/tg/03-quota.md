# 03 — Квоты на генерацию (P4)

Кратко: у каждого пользователя есть лимит генераций за скользящие 24 часа
(дефолт 10). При исчерпании запуск генерации отвечает `429`. Есть эндпоинт,
чтобы показать остаток в Mini App.

## Что считается

Каждый **запуск** генерации: `POST /api/v1/ppt/presentation/generate` и
`POST /api/v1/ppt/presentation/generate/async`. Неудачные генерации тоже
расходуют квоту (LLM-бюджет уже потрачен). `/edit`, `/derive`, превью,
экспорты — не считаются.

Не ограничены: суперпользователи. Режим `DISABLE_AUTH` — без лимитов.

## Ответ при исчерпании

- HTTP `429`, тело: `{"detail": "Generation quota exceeded, try again later"}`
- Заголовок `Retry-After`: секунды до освобождения ближайшего слота.

Боту: поймал 429 → покажи пользователю «лимит исчерпан, попробуй через
N минут/часов» (N из `Retry-After` или из `resets_in_seconds` ниже).

## Остаток квоты

`GET /api/v1/quota` (сессионная кука из 01-auth-telegram.md):

```json
{
  "limit": 10,
  "used": 3,
  "remaining": 7,
  "period_hours": 24,
  "resets_in_seconds": null
}
```

- `remaining: null` — безлимит (`limit <= 0`).
- `resets_in_seconds` заполнен, только когда лимит исчерпан.

Хороший UX: показывать остаток перед запуском генерации и не давать нажать
«сгенерировать» при `remaining: 0`.

## Конфигурация (на нашей стороне)

- `GENERATION_QUOTA_PER_DAY` в `.env` — дефолтный лимит (10), `0` = безлимит.
- Персональный лимит пользователя: `PUT /api/v1/admin/users/{user_id}/quota`
  с телом `{"limit": 25}` (`null` — вернуть дефолт). Админская кука.
- Поменять дефолт — без редеплоя кода, только env + перезапуск.

## Допущения

- Окно скользящее, не календарные сутки: слот освобождается ровно через 24ч
  после каждого запуска.
- Два одновременных запроса на последнем слоте могут пройти оба — превышение
  на единицу допустимо.
